# Chimera Product Charter

**Charter version:** 2.0.0

**Date:** November 17, 2026

**Product direction:** Familiar Authoring. Extensible Experiences. Transformative Learning.

Canonical local repository: `C:\inetpub\Chimera2`. The earlier checkout at

This charter governs product design and engineering direction. Its version is
independent of application releases. Existing delivery, security, permission and
acceptance requirements remain applicable. Surface conflicts for founder review;
do not silently reinterpret this charter or replace existing safeguards.

## Product identity

Chimera is a learning-experience transformation and authoring environment. It
ingests PowerPoint presentations, original authoring, Pythia consultation outputs
and artifacts, and supported external learning experiences. These sources can
be combined within one authored project.

## Authoring philosophy

Prioritize nontechnical instructional designers, educators and subject-matter
experts. Ordinary authoring must be familiar, direct, visually understandable
and usable without programming knowledge.

Avoid flow-programming metaphors, configuration dashboards, giant cards,
duplicate property panels and permanently displayed advanced controls. Reveal
advanced options when relevant without burdening ordinary authoring.

## Activity library

Provide recognizable, configurable learning activities using established
instructional interaction patterns. Preserve the underlying native experience
engine while separating its technical model from the author-facing editing
experience. Investigate H5P integration where useful, without assuming
compatibility or licensing rights.

## Advanced experiences

Support extensible ingestion contracts for external HTML5, simulation and
Unreal-derived experiences or specifications. Distinguish source specifications,
importable packages and executable runtimes. Never promise arbitrary external
execution or portability without qualification.

## Pythia relationship

Pythia provides optional, independent learning intelligence. Chimera provides
authoring, review, content persistence, playback and publication. Pythia
recommendations and artifacts must be inspectable and selectively accepted.
Human approval and existing revision and permission safeguards remain authoritative.

## Engineering constraints

Retain compatible project and scene models, asset provenance, history, revision
guards, permissions, learner playback and export behavior. Avoid parallel content
models or a second authoring engine. Preserve the classic application while
developing 2.0.

Work locally first. Do not merge, migrate, deploy or invoke paid generation
without explicit authorization. Preserve unrelated working-tree modifications.

## Acceptance philosophy

Qualify both engineering correctness and real usability. A passing automated
test does not establish that the authoring experience is intuitive and never
constitutes founder acceptance. Record machine verification and human review
separately; existing delivery and qualification gates remain in force.

Initial representative task:

> Create a scene, edit text, insert an image, add a ready-made activity, preview,
> save and reopen.

Defining multi-source task:

> Import PowerPoint, consult Pythia, retrieve and review generated content,
> incorporate selected changes, edit manually and publish.

These tasks define acceptance targets, not claims that every capability is
already implemented or qualified. Publication during verification remains
subject to explicit deployment authorization where applicable.
