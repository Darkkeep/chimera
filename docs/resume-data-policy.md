# Resume data policy

SCORM 1.2 packages use a conservative **4,096-byte** JSON/UTF-8 resume budget; SCORM 2004 4th Edition packages use **64,000 bytes**. ADL specifies character-based smallest permitted maxima; byte counting is deliberately stricter for Unicode portability. See the [ADL SCORM conformance requirements](https://www.adlnet.gov/assets/uploads/SCORM_2004_4ED_v1_1_TR_20090814.pdf) and [runtime reference](https://scorm.com/scorm-explained/technical-scorm/run-time/run-time-reference/).

The build report's `resumeData` section records the budget, conservative full-course maximum estimate, encoding and overflow policy. It warns when many scenes, audio completions, questions or long free-text responses could exceed that budget. This is a risk estimate, not an LMS compatibility certification or an arbitrary scene-count limit.

Before moving the LMS bookmark or writing scores/completion, the player measures the complete state. If it exceeds the budget, no state, bookmark or grade writes are attempted; previous saved progress remains intact and the learner sees a diagnostic explaining that current progress cannot be saved. Answers are not truncated. Rejected LMS writes/commits are reported and stop grade reporting for that save. The LMS API cannot provide a transaction across all fields, so successful state writes followed by rejected later fields must still be investigated through the visible diagnostic.

Existing JSON resume state remains readable; no migration or compression is required. Boundary tests cover exactly-at-budget and over-budget saves, Unicode byte counts, matching/ordering/written responses, remediation, failed commits and a 400-scene fixture. Small representative SCORM 1.2 LMS acceptance from October 14 remains historical evidence for that exact ZIP. Changed packages need operator acceptance in the target LMS; local harnesses do not provide that attestation.

Supported courses are those whose actual complete resume state stays within the selected profile's budget and whose target LMS accepts its calls. Use fewer tracked interactions, smaller course units or a qualified profile with more capacity if the build estimate flags a risk. Browser Preview uses browser storage; standalone courses retain state only while open and do not claim LMS persistence.
